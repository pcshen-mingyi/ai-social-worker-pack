# 個案訪視紀錄工具包

歡迎！這是明怡基金會的「AI 社工同事」體驗：用 Claude Code 走一次完整的個案訪視
紀錄流程——從逐字稿整理成正式紀錄 → 自動畫家系圖 → 寄給主管確認 → 核准歸檔 →
登打到明怡基金會個案管理系統。四個 skill 串成一條線，前一步完成會自動接續下一步，
你不需要記住名字或分別呼叫它們。

> 這是**體驗版**，資料都是示範用的假資料，不影響機構正式表單。系統本身
> （網頁、後台）不在這個工具包裡——那是已經架好、大家共用的網路服務，
> 這裡只負責產出訪視紀錄並送進去。

## 你收到的東西：一個資料夾，裡面有三層

打開「AI 社工同事體驗包」，裡面有三個資料夾：

```
AI 社工同事體驗包/
├── 個案訪視紀錄工具包/   ← 你正在看的這個，體驗的主角，skill 都放這裡
├── 明怡服務紀錄資料夾/   ← 示範「機構」的資料夾：個案資料表、核准後的歸檔都在這裡
└── 個人工作/             ← 示範「你（社工）個人電腦」的資料夾：
                            ├── 訪視原始資料/  ← 體驗用的示範家訪逐字稿（CASE-001、CASE-006 兩個案號），第一次體驗直接拿這個練習
                            └── （核准前的訪視紀錄草稿放這裡）
```

## 開始前：把三個資料夾放在同一層

這個工具包內建的路徑設定（`shared/config.json`）用的是**相對路徑**，只要求
「個案訪視紀錄工具包」、「明怡服務紀錄資料夾」、「個人工作」**三個資料夾放在
同一層**——不一定要放桌面，放在下載資料夾、隨身碟、公司共用磁碟都可以，只要
三者維持同一層的相對位置即可（不是放在「AI 社工同事體驗包」這一層資料夾裡面）。
請先把這三個資料夾**搬出來，放在你想要的位置、同一層**：

```
（你選的任何位置，例如桌面）
├── 個案訪視紀錄工具包/
├── 明怡服務紀錄資料夾/
└── 個人工作/
    └── 訪視原始資料/
```

## 體驗前不需要準備任何東西

**真的什麼都不用裝。** 不需要 Python、不需要 pip、不需要 npm，
也沒有「第一次執行要先安裝」的步驟。

所有腳本都用 Node.js 寫成，而 Claude Code 本身就帶 Node。畫家系圖需要的
中文字型與程式庫都已經放在這個資料夾裡（`shared/assets/`、`shared/vendor/`，
約 600KB），跟著資料夾一起帶走就能用。

其他設定（個案資料表路徑、主管信箱、你的姓名、系統網址、草稿/歸檔資料夾）
`shared/config.json` 都已經幫你填好體驗用的值，**不需要另外設定**：

| 設定項 | 已填好的值 |
|---|---|
| 個案資料表 | `明怡服務紀錄資料夾/個案資料表-demo.xlsx`（5 位示範個案，全部是假資料） |
| 主管信箱 | `wentest07@gmail.com`（示範用收件信箱，確認信會寄到這裡） |
| 訪視人員姓名 | `林社工` |
| 系統網址 | 明怡基金會個案管理系統（demo 版，請勿更改） |
| 草稿資料夾 | `個人工作/` |
| 歸檔資料夾 | `明怡服務紀錄資料夾/已歸檔/` |

**Gmail 授權**（③ 寄確認信要用，因為信是用「你自己的 Gmail 帳號」寄出）
**不用先做**。走到③需要寄信的時候，Claude 會自動偵測還沒授權，接著自動呼叫
`gcp-oauth-setup` skill，用 Claude in Chrome 把開專案、啟用 API、設定 OAuth
同意畫面這些步驟都做完，完成後會在 `shared/.credentials/` 底下自動產生
`token.json`——**這個資料夾和裡面的憑證檔案現在都還不存在，是走到③第一次
授權時才會自動建立**，不是你要事先準備的東西。
**全程只有一步需要你自己動手**：最後跳出瀏覽器「允許」畫面時，本人登入
Google 點一下——這是把「用你的帳號寄信」的權限交出去，AI 沒辦法也不能
代替完成。

如果想先了解或想自己手動跑，完整的手動步驟見
[`shared/references/google-api-setup.md`](shared/references/google-api-setup.md)：

1. 到 Google Cloud Console 建一個新專案、啟用 Gmail API
2. 設定 OAuth 同意畫面、加入 `gmail.send` / `gmail.modify` 兩個範圍
3. 建立「電腦版應用程式」類型的 OAuth 用戶端 ID，下載成 `client_secret.json`
4. 放到 `shared/.credentials/client_secret.json`
5. 執行 `node shared/lib/google_auth.mjs`，跳出瀏覽器按「允許」

做完之後（不管是自動還是手動），③④的 Gmail 相關功能就能正常運作。

> 如果只想體驗①②（整理訪視紀錄、畫家系圖），可以先跳過這一步，
> 用到③寄信時再回來設定即可。

## 開始體驗

搬完資料夾後，在**你剛剛放置的那個位置裡的**「個案訪視紀錄工具包」資料夾下開 Claude Code。
以下用「你是一位社工，剛家訪回來」的角度，走一次完整體驗：

**① 把逐字稿丟給 Claude**

你說：

> 「這是今天 CASE-001 的家訪逐字稿，幫我整理訪視紀錄」

Claude 會自己去 `個人工作/訪視原始資料/` 底下找對應案號的逐字稿檔案抓內容，
不需要你自己貼逐字稿文字（`訪視原始資料/` 裡固定放了 `CASE-001 訪視逐字稿.docx`
和 `CASE-006 訪視逐字稿.docx` 兩個示範案號可以練習，換成 CASE-006 一樣可以）。

Claude 會自己把身分欄位（姓名、身分證字號、電話、地址）從個案資料表寫進
docx——**這些內容不會出現在對話裡**，你只會看到「已成功寫入」；同時依逐字稿
草擬主述議題、評估、需求、處遇計畫，**不會停下來問你**，直接接著畫好家系圖、
嵌進同一份文件，才回報你：「訪視紀錄和家系圖都完成了，存在 XXX，你要先
檢查一下內容嗎？」

**② 你自己看一遍，確認沒問題**

打開檔案，重點看評估跟處遇計畫的判斷是否合理。覺得可以了，你說：

> 「可以寄給主管了」

**③ 寄信前先聽摘要**

Claude **不會直接寄出**，先念一次信件摘要給你聽（主旨、現況/需求/處遇計畫
三項摘要、結尾語句），你確認沒問題、說「可以」，才會真的用你的 Gmail 帳號
把 docx 附加寄給主管信箱（demo 用 `wentest07@gmail.com`）。

**④ 查看主管回信**

過一陣子，你說「查一下主管回信了沒」（可以自己用另一個信箱回信到
`wentest07@gmail.com` 模擬主管）。Claude 讀到回信後會告訴你：「主管回覆
看起來是核准，我理解正確嗎？」——**由你確認**，不是它自己判定就動作。

- 核准：Claude 把 docx 搬到「明怡服務紀錄資料夾/已歸檔」，問你要不要接著
  登打系統
- 退件：Claude 把主管的修改意見整理給你看，確認怎麼調整後，只改被要求的
  部分（不整份重寫），改完重新走一次③，直到核准

**⑤ 登打系統**

你說「好，幫我上系統」，Claude 用瀏覽器把訪視紀錄跟處遇計畫填進對應欄位，
**填完會停下來、截圖給你看，最後的「提交」按鈕永遠是你自己按**——不管你
怎麼說「你直接送」都一樣，這是刻意設計的安全閂。

你不需要記住上面五個步驟的名字或分別呼叫——只要開頭那句「幫我整理這次的
訪視紀錄」，就會從①自動接續到④。

## 流程總覽

```
逐字稿
    │
    ▼
① case-visit-record ──── 整理成正式訪視紀錄 docx（身分欄位自動帶入、
    │                     敘事內容由 AI 依逐字稿草擬），存到「個人工作」
    ▼
② case-genogram ──────── 自動畫家系圖，嵌入同一份 docx
    │
    ▼
③ case-visit-approval ── 寄信給主管確認，監看回信；核准就搬到
    │                     「明怡服務紀錄資料夾/已歸檔」，退件就回①依意見修改、重新走一次
    ▼
④ case-external-record-entry ── 登打到明怡個案管理系統（網頁），
                                  由你自己按下最後的「提交」按鈕
```

## 重要安全原則（已內建在 skill 裡，不需要你額外注意，但你應該知道）

- **身分資料（姓名/身分證字號/電話/地址）不會出現在對話紀錄裡**——
  ①的 `fill_identity.mjs` 直接讀 Excel 寫入 docx，Claude 只看得到「成功/失敗」
- **寄信前一定會先跟你確認內容**——③寄出確認信之前，Claude 會先念一次摘要
  給你聽，你同意了才會真的寄出
- **最後登打系統的「提交」按鈕一定要你自己按**——④會把表單填好、截圖給你看，
  但不會代替你按下送出，避免資料在你來不及檢查前就進了系統

## 如果之後要換成自己機構的真實資料

重跑 `node shared/lib/setup_config.mjs`，會用問答的方式讓你重新指定
個案資料表路徑、主管信箱、姓名、草稿/歸檔資料夾，取代這份體驗用的預設值。

```
    ├── case-visit-record/             ← ① 逐字稿 → 訪視紀錄 docx
    ├── case-genogram/                 ← ② 自動畫家系圖
    ├── case-visit-approval/           ← ③ 主管確認 + 歸檔
    ├── case-external-record-entry/    ← ④ 登打系統
    └── gcp-oauth-setup/               ← 用 Claude in Chrome 自動跑 Gmail 授權設定
```
