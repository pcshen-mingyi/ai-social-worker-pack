我要幫「個案訪視紀錄工具包」（明怡基金會「AI Builder 成長營」課程用的社工體驗包）加上公開下載發布流程，以及靜默、匿名的使用回報機制，並跟上小白包最新版的追蹤設計（含下載數漏斗）。

**先讀規格**：`個案訪視紀錄工具包_發佈與追蹤_開發規格與驗收標準.md`（跟這份開場指令放在一起，2026-08-13 更新版）。裡面的「前提」「明確非目標」「已敲定的細節」都仍然有效，不用再跟我確認一次。

**開工前務必先直接讀程式碼，不要只看文件摘要**——MYmate 小白包的統計後端一直在持續優化，`backend/程式碼.js` 目前的內容**比 CHANGELOG.md 記錄的還新**（已經包含每日下載數追蹤功能，CHANGELOG 還沒補上這段）。讀這幾份：
- `01_進行中/[PSF] MYmate(NPO Agent)/02_產出/04_模組落地包/MYmate-小白包/_stats.mjs`
- `.../MYmate-小白包/backend/程式碼.js`　←　**這份最準，程式碼本身比文件新**
- `.../MYmate-小白包/docs/統計設定-給維護者.md`
- `.../MYmate-小白包/CHANGELOG.md`（尤其 v1.9／v2.0，說明了目前這些設計決定背後踩過的坑，例如版本號被試算表判成數字、趨勢圖跳過空白日）

**依序做 M1 → M4**（規格裡都有；M4 拆成 M4a 事件計數、M4b 下載追蹤兩個子步驟），每個里程碑：**先寫測試再實作**，做完 commit、給我一句話簡短回報，等我確認才進下一個。

**最容易做錯的三條，測試先寫**：
1. 同一份資料夾第二次開 Claude Code 時，不會重複送出第二筆 `activate`（本地標記檔要生效）。
2. 修改 `doPost` 之後，對沒有 `product` 欄位的舊格式請求，仍然要寫進小白包原本的分頁、原本的欄位順序——用小白包既有的請求格式（不含 `product`）寫一個回歸測試，跑過再繼續。
3. 下載追蹤的 `fetchDownloads()`／`downloadSheet()` 參數化之後，小白包自己既有 repo 的下載數字要跟改動前完全一致——不能因為要支援第二個產品就把小白包自己的數字改壞。**不要為了這個包複製一份幾乎一樣的下載追蹤程式碼**，用參數化讓同一組邏輯服務兩個產品。

**正式服務相關的安全動作**：
- `backend/程式碼.js` 是**正在跑的服務**。動手改之前，先把現有內容存一份帶時間戳記的副本。
- 改完不要急著 `clasp redeploy`——先把 diff 給我看過，我確認之後你再重新部署**同一個部署 ID**（不要新建部署，否則舊網址會繼續跑舊碼）。
- 全程只能用假資料測試（工具包裡本來就有 `CASE-001`、`CASE-006` demo 資料可以用），不准用任何真實個案或真實 Gmail 帳號測試。

**里程碑收尾時額外檢查**：
- M1 做完：確認解壓縮後三個資料夾就在同一層，不需要使用者再手動搬移。
- M4a 做完：確認 `event` 白名單、20 字元截斷、不寫入 IP/User-Agent、版本平台存文字格式（`setNumberFormats("@")`）、每日趨勢用連續日期軸都做到了。
- M4b 做完：把改動前後小白包既有「下載」分頁的數字截圖或匯出 CSV 給我比對，證明沒被動到；新的「個案訪視工具包-下載」分頁能正確抓到 `mingyi-case-visit-kit` 的 Release 下載數。
