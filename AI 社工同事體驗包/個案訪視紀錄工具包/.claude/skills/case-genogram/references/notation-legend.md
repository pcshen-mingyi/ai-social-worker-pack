# 家系圖符號、稱謂與排版規則

採用標準家系圖規範（McGoldrick／Gerson 系統）。**這套系統全部是黑白線條，
不用顏色區分關係類型**——關係類型一律靠線型（實線/虛線/點線/鋸齒線）、線條
數量、斜線記號來區分。這點在課程開發過程中曾經做錯過一版（改用顏色區分），
已依專業教材（《家庭評估與會談案例》《家庭系統評估與會談》）校正回來，
之後修改請維持黑白線條，不要再加顏色。

## 成員符號

| 符號 | 意義 | JSON 對應 |
|---|---|---|
| □（方形，無填色） | 男性 | `"gender": "male"` |
| ○（圓形，無填色） | 女性 | `"gender": "female"` |
| 符號內打 X（兩條對角線貫穿） | 已故 | `"deceased": true` |
| **雙線框**（同心雙方框／雙圓圈）＋符號畫得比同代其他人**更大** | 索引個案（案主，IP） | `"is_index": true` |
| 男性方框右半邊填黑 | 持有身障手冊 | `"disabled": true` |
| │（垂直線） | 親子關係 | `"type": "parent"`（由父/母 a 指向子女 b） |

索引個案的標示**不是紅色框、不是虛線圈**——這是先前版本的誤解，已修正。
正確畫法是雙線框（框線本身用兩條同心線），加上符號整體放大。教材範例裡索引
個案也會刻意畫得比手足略低，但那是手動排版才能做到的細節；我們這裡是自動
排版，若比照著做會在索引個案有配偶時破壞「配偶必須同一世代高度並排」的
版面（配偶連接線會變成斜線），兩害相權，目前**只做放大＋雙線框，不做位置
下移**，這是已知的簡化。

## 伴侶狀態（互斥，最多擇一，全部是線上的記號，純黑白）

| 樣式 | 意義 | JSON `type` |
|---|---|---|
| 實線 | 結婚 | `married` |
| 實線＋線上一個朝下小三角形 | 同居承諾關係（LT, living together） | `cohabiting` |
| 實線＋線上一道斜線「/」 | 分居 | `separated` |
| 實線＋線上兩道斜線「//」 | 離婚 | `divorced` |

## 情感關係（可與伴侶狀態疊加）

| 樣式 | 意義 | JSON `quality` |
|---|---|---|
| 雙實線 | 親密 | `close` |
| 三實線 | 過度親密／融合（enmeshed） | `enmeshed` |
| 點線 | 疏離 | `distant` |
| 鋸齒線 | 衝突／敵意 | `conflict` |
| 雙實線＋鋸齒線疊加 | 衝突又親密（矛盾關係） | `conflictClose` |
| 線上兩道短橫槓（切痕） | 溝通中斷 | `cutoff` |

`quality` 可以獨立使用（不需要同時填 `type`），例如手足之間沒有伴侶關係，
但想標記「疏離」，直接給一個只有 `quality` 沒有 `type` 的 relation 即可。

## 雙胞胎（簡化實作）

正規畫法是兩條子女線收斂於同一點（同卵雙胞胎再加一條橫槓連接兩線），但這個
畫法在目前的自動排版邏輯下容易跑版，**目前簡化為在姓名旁加註「（雙胞胎）」
或「（同卵雙胞胎）」**，子女連接線仍照一般手足並排處理：

```json
{"id": "m3", "name": "案兄", "gender": "male", "generation": 1, "twin_group": "t1"},
{"id": "m4", "name": "案主", "gender": "female", "generation": 1, "twin_group": "t1", "identical_twin": true, "is_index": true}
```

## 成員稱謂（`name` 欄位固定用稱謂，不要填真實姓名）

一律以**案主為中心**的稱謂，不要用「王先生」「長女」這種姓名或籠統代稱：

| 關係 | 稱謂 |
|---|---|
| 服務對象本人 | 案主（如有第二位服務對象，見下方「次案主」） |
| 案主的父／母 | 案父／案母 |
| 案主的祖父／祖母（父系） | 案祖父／案祖母 |
| 案主的外祖父／外祖母（母系） | 案外祖父／案外祖母 |
| 案主的配偶 | 案夫／案妻（同居伴侶可用「案伴侶」） |
| 案主的子／女 | 案子／案女 |
| 案主的孫／孫女 | 案孫／案孫女 |
| 案主的手足 | 案兄／案姊／案弟／案妹（依出生順序比案主年長用兄/姊，較年幼用弟/妹） |
| 第二位服務對象（同一案家有多位案主時） | 次案主 |

**手足排序**：如果同一世代手足超過一位、需要標示長幼順序，用 `note` 欄位加註
稱謂，例如 `{"name": "案兄", "note": "大哥"}`，畫出來會顯示「案兄（大哥）」。

**`note` 欄位只用於長幼排序稱謂**，不要放病名、收入、職業、居住狀況等生活資訊。

## 世代範圍：自動判斷，不用讓使用者選

**不要在對話中問使用者「要往上幾代還是往下幾代」**，這件事本身應該由案主的
年齡/身份類型自動決定：

| 案主類型 | 世代範圍 |
|---|---|
| 幼兒青少年案主（18 歲以下） | 以案主為中心，往上兩代（案父母、案祖父母／外祖父母） |
| 中壯年案主（18–64 歲） | 以案主為中心，往上下各一代（案父母、案子女） |
| 老年案主（65 歲以上） | 以案主為中心，往下兩代（案子女、案孫子女／外孫子女） |

判斷方式：

1. 優先執行 `scripts/classify_scope.py --case-id {案號} --data {shared/config.json 的 case_data_xlsx}`
   （路徑同 `case-visit-record` 步驟 2 用的 xlsx）。這支腳本只會回報年齡區間分類
   （例如「老年案主｜scope=down2｜……」），**不會印出實際出生年月日**，維持身分
   資料不經過你的原則。
2. 如果查不到（互動訪談模式、案主不在資料表裡），改用逐字稿/對話裡的年齡線索
   （案主自述幾歲、「阿嬤」「國小」「退休」等稱謂或描述）自行判斷屬於哪一類。
3. 判斷後直接依對應範圍萃取/詢問成員，不用把「幼兒青少年/中壯年/老年」這個
   分類結果或世代範圍選項丟給使用者選——這是系統該幫使用者做的判斷，不是
   使用者的工作。

## 排版規則

1. **世代分行**：世代編號越小（越年長）畫面越上面，`generation: 0` 在最上層。
2. **配偶並排相連**：同世代的伴侶會被拉近排在一起，中間依伴侶狀態畫對應線條。
3. **子女在下方以垂直線連接**：從父母之間往下拉一條線到子女那一排，多個子女
   在父母正下方左右展開；如果子女本身也有配偶，整個配偶單位會一起移動，
   不會拆散。
4. **手足由左到右排列**：子女依 JSON 裡 `members` 陣列的順序由左到右排列。

## 資料規則（比照專業家系圖工具的慣例）

1. 如果 AI 未能從逐字稿/對話擷取完整或正確的資訊，在「與使用者確認」的表格
   步驟裡讓使用者直接說要修改哪裡（不需要額外的圖形化編輯介面，用文字對話
   修正即可）。
2. 每一位成員都必須至少與另一位成員存在親子或伴侶關係，才有意義被畫進家系圖——
   沒有任何關係的孤立成員不要加進 `members`。
3. 親子關係一律由 relations 裡 `type: "parent"` 的 `a`（父/母）→`b`（子女）表示，
   等於是從子女的角度定義「我的父母是誰」。
4. 若同時存在多種親密關係／情感關係，最多同時呈現兩種樣式（一個 `type`＋一個
   `quality`），不要在同一對關係人之間疊加三種以上樣式。
5. 需要標示長幼順序時用 `note` 欄位加註稱謂（見上方手足排序說明）。
6. 如果案家同時有兩位服務對象，第二位用 `name: "次案主"`、`is_index: true`
   標示（次案主一樣會有雙線框放大標記）。

## 已知限制

- 這是自動啟發式排版，不是完整的家系圖排版引擎。成員很多、關係很複雜（例如
  多次婚姻、隔代教養、非直系收養關係）時，畫面可能會擁擠或線條交錯，需要
  人工檢查、必要時手動調整 JSON 裡的 `generation` 或成員順序後重新產圖。
- 情感關係（`quality`）線目前以「兩人之間直線疊加」呈現，如果兩人之間剛好
  隔著其他成員的符號，線條可能會從該成員符號後方通過，屬已知的排版限制。
- 雙胞胎目前簡化為文字加註（見上方說明），沒有畫收斂式雙胞胎連接線。
- 懷孕（三角形）、流產（小圓點）、死胎（小方塊內打X）、墮胎（小三角形）等
  家系圖延伸符號目前尚未實作，如果個案需要這類資訊，先用文字記錄在敘事
  段落裡即可，不用勉強塞進家系圖。
- 中文字型透過系統既有 CJK 字型渲染（例如 macOS 的 Heiti TC / PingFang TC），
  若在缺少對應字型的環境執行，人名可能會顯示成方框或亂碼，請確認執行環境有
  安裝中文字型。
